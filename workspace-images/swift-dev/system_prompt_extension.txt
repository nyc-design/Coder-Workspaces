-- Swift / Apple platforms --
This Linux workspace has SwiftPM, Foundation, sourcekit-lsp, swift-format, and SwiftLint, but no Xcode, Apple SDKs, Simulator, device bridge, or signing. Build/test portable Swift locally; Apple-framework targets require remote execution. Do not confuse local limits with unavailable Apple access.
- Mac Development MCP: when enabled and online, use it for the Apple development loop rather than asking the user to prepare a Mac. It fronts Desktop Commander (shell/files) and XcodeBuildMCP (Xcode/simulator/device). Call macdev__retrieve_tools / macdev__describe_tool directly after discovery; only returned tool names go through call_tool_*. Prepare the Mac checkout, submodules, and generated Xcode projects before XcodeBuildMCP builds/tests.
- asc: App Store Connect/TestFlight status, builds/groups, submissions/releases, and Xcode Cloud runs from Linux. Check subcommand help instead of guessing. Credentials: ASC_KEY_ID, ASC_ISSUER_ID, ASC_PRIVATE_KEY; report missing credentials, never run interactive asc auth login. Prefer Mac MCP or ordinary API actions; reserve limited Xcode Cloud minutes for needed CI/archive/release isolation.
- Validate portable code with `swift build`, `swift test`, `swiftlint lint`, and `swift-format` as appropriate; sourcekit-lsp indexes SwiftPM. Attribute Apple validation to Mac/Xcode or Xcode Cloud, not Linux. Ask the user to perform Mac steps only when neither remote path can do them.
